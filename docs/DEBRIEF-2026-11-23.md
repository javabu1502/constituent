# My Democracy: Security and Usage Debrief

**Prepared 2026-11-23 · My Democracy LLC · Internal**

This is a two-part review: a security audit of the live platform, and an
honest account of how much the product is actually being used. Every number
below was read from the production database or tested against the live site
on 2026-11-23. Nothing here is estimated.

---

## 1. Headline

Security is in good shape. The application-layer controls hold up under
direct testing, and the one material finding is dependency patching.

Usage is the problem. The platform works, delivery works, and almost nobody
is using it. **No external organization has signed in since the day its
account was created.** Three paying agreements are out for signature against
a product that has not yet held a customer's attention past onboarding.

---

## 2. Security audit

### 2a. What was tested

| Area | Method |
|---|---|
| Row level security | Static sweep of all migrations, then live reads with the public anonymous key |
| Route authorization | All 90 API routes surveyed, then unauthenticated requests against admin and cron endpoints |
| Transport and browser policy | Live response headers |
| Dependencies | `npm audit` against production dependencies |
| Secrets | Repository scan for committed credentials |

### 2b. Findings

**HIGH — 24 known vulnerabilities in dependencies, 9 rated high.**
Every one has a fix available. `ws` (uninitialized memory disclosure),
`sharp` (inherited libvips CVEs), `postcss` (XSS via unescaped style output),
`js-yaml`, `nanoid`, `picomatch`, `brace-expansion`, `browserslist` and
`source-map-js` are all high. `next` and `resend` carry moderate advisories.
Most are build-chain rather than request-path, which lowers the practical
risk, but the count is the symptom: there is no automated dependency
alerting. No Dependabot configuration exists, and no `npm audit` or license
check runs in CI. Nothing tells you when a dependency becomes vulnerable.

**LOW — Admin page shells render to anonymous visitors.**
`/admin/campaigns`, `/admin/compliance` and `/admin/cwc-queue` return 200 to
an unauthenticated request. They are client components that hold no data;
every one of them loads from `/api/admin/*`, which correctly returns `403
Forbidden` with no body. No data is exposed. The only leak is that the admin
surface is discoverable.

**LOW — `script-src` allows `unsafe-inline`.**
Standard for a Next.js application and not trivially removable, but it is the
one weak clause in an otherwise strict policy.

**Carried forward, already documented in the Security Overview §10:** no SOC 2
or ISO 27001 of your own, no third-party penetration test, no point-in-time
recovery, no restore ever exercised from a production backup, no formal
written policy manual. Backups are daily with seven-day retention and sit in
the same AWS region as the primary database, so a regional failure takes both.

### 2c. What is working

Tested directly, not taken on trust:

- **Row level security is live and effective.** The public anonymous key
  returns HTTP 200 and **zero rows** on `messages`, `profiles`, `stories`,
  `campaigns`, `campaign_actions`, `message_compliance`, `org_requests`,
  `story_subjects` and every other table tested. Every table created in
  migrations has an explicit enable statement.
- **Admin APIs reject cleanly.** 403 with `{"error":"Forbidden"}` and no
  information in the body.
- **Cron endpoints reject cleanly.** 401 without the shared secret.
- **Token-gated public routes are correctly gated.** Story permission,
  campaign-update unsubscribe and notification unsubscribe all verify an HMAC
  before touching the database. The story permission update is additionally
  constrained to rows still in `requested` status, so an answered request
  cannot be replayed.
- **Transport and browser policy is strong.** HSTS with `preload` and a
  two-year max-age, a full Content Security Policy with `frame-ancestors
  'none'` and `object-src 'none'`, `X-Frame-Options: DENY`, `nosniff`,
  `strict-origin-when-cross-origin`, and camera, microphone and geolocation
  all disabled at the header.
- **No credentials in the repository.** Only `.env.example` is tracked.

### 2d. Attack surface removed today

The Bluesky social desk was deleted outright: the agent, four cron jobs that
ran every two hours, the publish route and roughly 4,500 lines. It had been
paused since September but remained one database flag from live. The news
aggregation feature and its two public API routes were removed as well. Both
reduce the surface and remove the autonomous-publishing risk entirely.

## 3. Usage audit

### 3a. Scale, separating real from seeded

| | Total rows | Seeded demo | **Real** |
|---|---|---|---|
| Campaigns | 134 | 41 | **93** |
| Messages | 1,165 | 1,080 | **85** |
| Stories | 43 | 34 | **9** |
| Distinct people | 67 by email | 51 | **16** |

41 campaigns carry the `demo-` prefix. **93% of all message rows in the
database are synthetic.** That is not a problem in itself; it is what makes
demos possible. It does mean every dashboard number has to be read carefully.

### 3b. Who is actually using it

**85 real messages from 14 distinct advocates over ten months.** 71 of those
messages were sent anonymously; only 14 came from a logged-in account.

Monthly real message volume: Feb 17, Mar 6, Jun 16, Jul 9, Aug 1, Sep 5,
Oct 16, Nov 15. Flat. No growth trend in either direction.

38 profiles exist, with signups arriving steadily at two to seven a month.
25 of them carry a street address.

**Every external organization last signed in on the day its account was
created, or the day after.** Not one has come back.

This is the single most important number in this document. It is more
important than any security finding, because it is the one that decides
whether WECA, GEEARS and Nevada Children's Lobby renew after their first
term.

Related: of 93 real campaigns, **89 are official My Democracy weigh-ins and
only 4 were created by an organization.** The org product — the thing being
sold at $1,000 to $1,200 a term — has four campaigns to its name.

### 3d. Delivery is working

Of 85 real messages:

| Outcome | Count |
|---|---|
| Email opened | 55 |
| Email copied | 11 |
| CWC delivered | 14 |
| Webform delivered | 1 |
| CWC refused | 2 |
| CWC failed | 1 |
| Webform failed | 1 |

**17 CWC attempts, 14 delivered: an 82% success rate** against the official
House and Senate systems. The delivery pipeline, which was the hardest thing
to build, is the part that works.

### 3e. Data quality

Three issues worth fixing, none urgent:

1. **Duplicate Children's Cabinet accounts.** Two separate org profiles,
   differing only by a curly versus straight apostrophe in the name, with
   different slugs and different staff emails. Campaigns and stories created
   under one are invisible to the other.
2. **Nevada Children's Lobby has a null `org_slug`.** Every other
   organization has one. Anything keyed to the public org page will not
   resolve for them.
3. **21 real messages have a null `legislator_level`.** Roughly a quarter of
   real traffic cannot be attributed to federal, state or local in reporting.
4. **The "Advocacy" org account** (advocacy@mydemocracy.app, never signed in)
   appears in the data as a real organization and inflates the org count.

## 4. Recommendations, in order

**1. Find out why organizations do not come back.** Call Children's Cabinet.
They have had an account since July, a second one since September, and have
opened neither since the day each was made. Whatever the answer is, it
applies to WECA and GEEARS too, and it is cheaper to learn it now than after
three renewals do not happen.

**2. Turn on Dependabot and add `npm audit` to CI.** Free, roughly ten
minutes, and it closes the one material security finding. It also makes
"immediately upon availability" a defensible answer on the insurance
application rather than an aspirational one.

**3. Run `npm audit fix`.** All 24 advisories have non-breaking fixes
available. Do it, run the suite, ship it.

**4. Test a restore from a production backup, once, and write down how long
it took.** It closes the honest gap in Security Overview §10 that says no
restore has ever been exercised, and it tells you whether your real recovery
time is four hours or thirty. Right now nobody knows.

**5. Copy a periodic `pg_dump` to a second region.** The database is small.
Backups currently live in the same region as the primary, which is the one
failure mode daily backups do not protect against.

**6. Clean up the org data.** Merge the two Children's Cabinet accounts,
backfill the Nevada Children's Lobby slug, delete or clearly mark the
"Advocacy" account, and backfill `legislator_level` where it is null.

**7. Before the GEEARS and WECA signatures:** update Security Overview §10,
which currently tells every organization that reads it "Cyber liability
insurance: Not currently carried," and rebuild their document sets from the
templates.

---

## 5. Honest summary

The platform is well built and well defended. Row level security holds, the
headers are strict, the secrets are clean, the congressional delivery
pipeline works at 82%, and the surface got smaller today.

The risk to this business is not a breach. It is that three organizations are
about to sign agreements for a product that, so far, no organization has
opened twice.
